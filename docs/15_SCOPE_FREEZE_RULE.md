# ResolveOps AI — Scope Freeze Rule

Before a paid package is offered, write down every included capability and freeze that scope.

During launch hardening, new optional features do not enter the release. Work is limited to finishing promised capabilities, fixing defects, completing tests, security, deployment, monitoring, backups, restore, onboarding, and documentation.

If a new customer request is genuinely required for the promised outcome, it is added to the scope and must be completed before that revised package is sold. If it is optional, it remains outside the current package and can be planned for a later complete version.

The purpose of this rule is to achieve two goals at the same time:

- never charge for an incomplete promised package;
- never allow the word "complete" to expand into an endless list of future ideas.

The launch target is a narrow, valuable, fully completed package.
