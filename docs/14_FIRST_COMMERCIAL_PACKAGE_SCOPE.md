# ResolveOps AI — First Complete Commercial Package Scope

## Product name

**ResolveOps AI Support Intelligence and Agent Assistance**

## Purpose

This file defines the smallest complete product ResolveOps should finish before beginning normal paid client sales.

The objective is to avoid two bad extremes:

1. selling unfinished promised functionality; or
2. waiting until every future idea in the multi-year roadmap is complete.

The package below is intended to be small enough to finish quickly and valuable enough to sell as a complete product.

## Promised outcome

A support team should be able to use its approved historical support knowledge to find reliable answers faster, draft evidence-backed responses, preserve customer and conversation context, escalate uncertain cases to humans, and give managers clear visibility into quality and operational performance.

## Included capabilities

### 1. Secure accounts and permissions

Users can sign in and receive only the permissions appropriate to their role.

### 2. Workspace data separation

Each client's support data stays inside its own workspace.

### 3. Supported historical data import

At least one production-supported import path is fully usable.

For the first package, a hardened CSV import is sufficient if that is what sales promises.

### 4. Evidence-backed support search

Support agents can ask questions and retrieve relevant information from approved historical support knowledge.

### 5. AI answer drafts with citations

The system drafts an answer and identifies the sources supporting it.

### 6. Safe uncertainty behavior

If evidence is weak, the system does not pretend to know. It asks for clarification, refuses to answer, or recommends human involvement as appropriate.

### 7. Customer and conversation context

Agents can see the relevant conversation and customer history stored in ResolveOps.

### 8. Human escalation

The system can transfer an uncertain or sensitive case to a human without losing previous context.

### 9. Reliability and management visibility

Managers can see quality, failures, usage, escalations, and relevant operational metrics.

### 10. Production operating foundation

The sold release has repeatable deployment, monitoring, backups, tested restore, incident procedures, security checks, end-to-end tests, onboarding instructions, and clear support ownership.

## Explicitly excluded from the first package unless specifically completed before launch

- live Zendesk integration;
- live Freshdesk integration;
- live Intercom integration;
- WhatsApp;
- SMS;
- voice;
- fully autonomous refunds;
- fully autonomous cancellations;
- high-impact external account changes;
- MCP server;
- developer SDK;
- enterprise SSO;
- advanced product-intelligence mining;
- complex usage billing;
- integration marketplace.

These are not unfinished pieces of the first package if they are clearly excluded before the promise is made.

They become future package capabilities.

## Rule for client-specific requirements

If a client cannot use the package without a capability currently listed as excluded, choose one of two paths:

1. complete that capability before selling the revised package to that client; or
2. do not sell that package to that client yet.

Do not sell the incomplete package at a lower proportionate price.

## Completion standard

Every included capability must have:

- working normal flow;
- usable failure flow;
- permission checks;
- workspace isolation;
- appropriate sensitive-data handling;
- automated tests;
- end-to-end validation;
- deployment proof;
- documentation;
- operational ownership.

## Commercial launch condition

The first package becomes sellable only after every included capability passes the completion standard.

> **The target is not the largest possible first product. The target is the smallest complete product that creates enough value for a support team to pay for it.**
